## The rule everything here serves

Operator, 2026-10-13, in capitals: **NEVER test ATC against the development or production database. Always
seed from the emulator and never query the actual database.** It narrows (does not lift) the old absolute ATC
ban: ATC may now be exercised, but only against the emulator. Three layers enforce it, deliberately redundant:

| Guard | Where | What it catches |
|---|---|---|
| G1 | `atc/seed-atc.js` top | refuses to run (exit 3) unless FIRESTORE / AUTH / STORAGE emulator hosts are set AND local. No cloud path exists by design. Verified: bare `node atc/seed-atc.js --seed` exits 3. |
| G2 | `atc/support/atc.ts` `installAtcGuards` | aborts EVERY browser request to `firestore/firebasestorage/storage.googleapis.com`; any database-shaped one fails the test in `afterEach`. |
| G3 | `atc/emulator-wiring.spec.ts` | a doc that exists ONLY in the emulator's `firestore-atc` must render — positive proof of the wiring. |

## WHY main.ts had to change (the blocker)

`src/main.ts`'s emulator branch connected only the DEFAULT Firestore. Every ATC screen calls
`getFirestore("firestore-atc")` itself, so under the emulator build that handle pointed at the REAL cloud
project — exactly what the rule forbids. One line now connects it (`connectFirestoreEmulator(getFirestore(app,
'firestore-atc'), …)`). Without it G3 fails and G2 records the real-DB traffic.

## Surprise 1 — the "named DB client access is DENIED" note is stale

`ci/overlay/firebase.emulator.json`'s `//firestore` note says the emulator can't give a named DB rules, so
client reads/writes to it are denied (that's why profiles PA-13/14 skip on the emulator). Probed today on
firebase-tools 14.4 / firestore emulator 1.19.8: an UNAUTHENTICATED REST write + read to `firestore-atc`
**succeeded**, and data is isolated from `(default)`. Recorded in the `//databases` note. NOT re-verified for
`firestore-forms` — PA-13/14 may now be runnable on the emulator; worth a look (not done here).

## Surprise 2 — G2 tripped on the app's branding images (refined, still aborts everything)

First run: all 9 cases failed G2 on three URLs — `firebasestorage.googleapis.com/v0/b/fir-sample-aae4a…/o/
AH Logo…png?alt=media` and a default-avatar png. The app shell hard-codes these PRODUCTION-bucket download
URLs as `<img src>`. They are not a database access, and G2 had already aborted them (nothing left the browser).
Refinement: G2 still **aborts every** real Firestore/Storage request; it now **fails** on any Firestore call
and any Storage call that is not a plain `GET …/o/<file>.(png|jpg|svg|gif|webp)?alt=media`. Those static-image
GETs are recorded in `guard.staticAssetBlocks` instead. A mis-wired `firestore-atc` (firestore.googleapis.com)
or a mis-wired upload (POST …?uploadType) still fails the test.

## Surprise 3 — the cloud ATC guard would have blocked the seed

`seed.teardownCollections()` calls `assertNoATC()`, which `process.exit(3)`s on any collection matching
`/\batc\b/` — including the reference-only `atc model`. That guard is right for the CLOUD path. The ATC seed
therefore does its own teardown (default DB: by `testrunid`; `firestore-atc`: `recursiveDelete` of the ATC
collections, including app-written versions/drafts/conflicts that carry no tag). That is safe ONLY because G1
pins the whole process to the emulator — do not copy this teardown into a seeder without G1.

## Smaller decisions (all inside the locked plan's intent)

- **One participant per Prescribe case** (seed roster grew to p0..p7). A case's leftover autosaved draft
  otherwise opens the draft picker in a later case for the same participant.
- **One seeded ATC per Edit case** (E1..E6, EV1). A save UPGRADES the ATC (old → `upgraded/isdelete`, new
  version with `editedfrom`), so an edit is not repeatable on the same doc.
- **View counts are computed live** from the emulator (Prescribe/Edit add and retire ATCs in the same run).
- **mat-select clicks go to the enclosing `mat-form-field`** — an empty outline field's floating `<mat-label>`
  intercepts a direct click (VATC-02's first failure).
- **VATC-07 applies to the SECOND activity (Support Agent)**, not Change Agent, so the legacy
  `assigned_to`-only procedure proves its agents are mapped under the FIRST activity and kept.
- **VATC-05b asserts "close without validator still validates"** — operator: validator is optional; intended.
- `data-testid` prefixes: `patc- eatc- vatc- atco- aael- selv- pabs- dcfl-` (≈110 hooks, additive only).

## Result (two full runs, identical)

24 / 25 pass, ~1.5 min. G3 + VATC-01..07 + PATC-01..08 + EATC-01..06, 08 green.

**EATC-07 fails — a real app bug, not a test bug.** `edit-atc.component.ts` `updateATCnotes()` (~1391-1395)
only merges the uploaded audio/image URLs when the ATC ALREADY had notes (`existingNotes != null`). For an ATC
with no prior notes `audiodata`/`imagedata` stay `[]`, so the new notes doc is written with
`changeworkbrief: []`, `imagenotes: []` — the files ARE in Storage (verified in the emulator:
`ATC_Audio_Notes/atc_pf_admin/New Audio - 1 …`) but the ATC no longer references them. The ATC image survives
(`prescription_image`). Fix (not applied — needs operator sign-off): in the `else` case use `audiobrief` /
`imagenotes` directly. The test is left asserting the CORRECT behaviour.

### Update — fix applied (operator-approved), suite fully green

Narrowing found while explaining it to the operator: the bug only triggers when the edited ATC has NO notes
doc (`notesid` null or pointing at a missing doc). Today's Prescribe always creates `atc_notes`, so normal ATCs
never hit it — only legacy / other-source ATCs can. The test seeds `notesid: null` deliberately.

Fix (`edit-atc.component.ts` `updateATCnotes`): `let audiodata = [...audiobrief]; let imagedata = [...imagenotes];`
instead of `[]` — the existing-notes branch is unchanged (old first, then new). A proposed `concat` variant was
rejected: `audiodata.concat(…)` without assigning the return value discards the merge and would have WIPED
existing changework audio on every text-only edit of a normal ATC.

Re-run: **25 / 25 pass** (1.7 min). Gotcha: a leftover `ng serve` from earlier was still bound to :4200 and was
serving a STALE bundle (old `let audiodata = [];`) — verify the served chunk before trusting a re-run.

### Update 2026-10-14 — console readiness blocked offline-ATC: "New elements no spec references"

WHY: `scripts/readiness/lib.cjs` (`TESTID_REF`) only counts a hook as referenced when the spec contains it as a
LITERAL `data-testid="x"` or `getByTestId('x')`. The specs used a `tid('x')` helper that builds the selector at
runtime → the checker saw ZERO references (tested=0 on all 7 components). Fixed hub-side, no behaviour change:
104 `X.locator(tid('id'))` → `X.getByTestId('id')`. **Rule for this suite: always write hooks as literal
`getByTestId('…')`** (bound/indexed hooks like `patc-adj-${i}` are not counted by the checker either way).

That left 25 hooks no test used at all. Operator chose "add tests for them": PATC-05 (+3rd device declines
the draft with Close), PATC-09 (Edit Directive, Recommended To, Mandatory + Completed, summary, AEL Go Back),
EATC-09 (Update Directive, edit adjustment text, Delete Adjustment Completely, procedure delete toggle,
Mandatory, summary + points, preview Close), VATC-08 (mentor + queue filters, 'validated' status text), and
VATC-01/03/07 additions (loading bar, Adjustments/Change Work totals, assigned names, bulk box). Seed grew:
p8, E7, M1, Q1 + a `queue generation` / `arena events` pair. The readiness element check, reproduced locally
against the real development base (fetched with `gh api`, since git is blocked here): **all clear**.

Re-run: **28 / 28 pass** (1.9 min).

### Update 2026-10-14 (2) — "Selectors gone from the app"

The literal-getByTestId conversion over-reached: it also made INDEXED/KEYED hooks literal (`patc-adj-0`,
`vatc-adj-0`, `eatc-exadj-0`, `eatc-exproc-1`, `eatc-newproc-0`, `atco-draft-select-0`, `dcfl-keep-mine`). The
app declares those as `[attr.data-testid]="'x-' + i"`, so it holds no literal copy, and the DRIFT half of the
check (`findDriftedSelectors`) reported them as gone. Fix: those 7 go back through `.locator(tid(...))`, which
neither half of the check reads. The rule now sits at the top of prescribe-atc.spec.ts. Gotcha found on the
way: the checker also reads COMMENTS — a literal example in a comment was itself flagged as a drifted selector.
Both halves reproduced locally: drifted `[]`, elements all clear. Suite re-run: 28 / 28.
